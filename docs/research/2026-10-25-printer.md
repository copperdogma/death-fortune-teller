# Native thermal printer transport research — 2026-10-25

## Problem class

The printer is a slow UART peripheral that can occupy a caller for many seconds. A fortune flow must keep the application/audio loop responsive, bound memory use, and pace printer input without claiming physical-print completion when the printer offers no verified acknowledgement path.

## Sources reviewed

- Espressif, [ESP-IDF UART driver reference](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/peripherals/uart.html): the installed UART driver buffers TX and exposes `uart_write_bytes`; writes with no TX buffer can wait until data reaches the FIFO. This supports a dedicated task with an installed finite TX buffer rather than transmitting from the application/audio callback.
- Epson, [ESC/POS LF reference](https://download4.epson.biz/sec_pubs/pos/reference_en/escpos/lf.html) and [command index](https://download4.epson.biz/sec_pubs/pos/reference_en/escpos/commands.html): LF prints buffered text and advances one line; ESC @ initializes the printer. The CSN-A1X is a compatible third-party device, so Epson behavior is a useful protocol reference, not proof of full command compatibility.
- Locally supplied Cashino CSN-A1X manual, `docs/hardware/.../CSN-A1X-1.pdf`: identifies 9600–115200 bps serial support and describes BUSY/RTS flow control as a configurable printer feature. The current board/harness has not demonstrated a connected BUSY/RTS signal or its configured polarity.
- Existing `src/thermal_printer.cpp` and `docs/stories/story-005-thermal-printer-fortune.md`: the legacy implementation includes synchronous response polling; historical logo/justification formatting changes caused garbage output. Existing hardware reports working text output at 9600 baud, but the native target has not yet been exercised on hardware.

## Decision

Use UART1 on TX GPIO18 / RX GPIO19 at 9600 8N1, a FreeRTOS worker, and a fixed two-job queue with a 1024-byte maximum fortune. The worker sends a short ESC @ initialization, ASCII-only text wrapped to 32 columns, LF line breaks, and a small delay after each line. Queue submission and cancellation do not wait for printing. Leave bitmap/logo commands out until the native transport and text path are proven on the actual CSN-A1X.

## Uncertainty and next validation

UART write success only means bytes were accepted by ESP-IDF, not that paper advanced or the printer completed. The installed wiring's BUSY/RTS connection and printer status-response behavior remain unverified; this module reports transport-level job completion only. Hardware validation should check readable wrapping, sustained throughput, cancellation, and that the audio path remains responsive while the printer is active.
